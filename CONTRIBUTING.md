# Tessuno contribution process

Original scaffold work is licensed Apache-2.0. The license governs contributions to the extent
applicable; no separate DCO, CLA or additional contribution agreement is adopted here.
GitHub account `sha-shank-03` is the maintainer and contribution triage owner.
Public collaboration is intended once repository creation and push are verified.

Use a small issue for a non-sensitive bug or proposal and a focused pull request for a change.
Describe the problem, scope, provenance and validation results; link a related issue when useful.
The maintainer reviews the exact diff and may request independent review for contracts, gates,
adapters, build tooling or workflows. No acceptance or response time is guaranteed.
Follow SECURITY.md for reporting status; do not post vulnerabilities, exploit details,
private evidence or secrets in public issues, pull requests, discussions or comments.

Use original synthetic content and document provenance; do not import arbitrary third-party Skills.
Every change includes affected contracts, valid and invalid fixtures, authority changes, limitations,
and commands/results. Declare whether you authored the implementation you review.

Review schemas, adapters, build tooling, security gates and proposed workflows independently.
Never treat contributor-provided pass records, signatures, generated archives, or model-written
reviews as verified provenance. Protected checks must come from a reviewed trusted revision.
After a change to covered content or action scope, prior approvals are stale. Review the exact
new digest. Public source availability follows docs/source-preview-policy.md and grants
no execution authority, trusted badge, qualified release, CI activation or deployment.
